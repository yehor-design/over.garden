# OverGarden — Дослідження інструментів «двигуна зведення» (_README / маніфест)

**Що це:** маніфест deep-research дослідження інструментів matching/dedup-двигуна (9 задач), виконаного проєкт-обізнаним AI-оркестратором + 9 саб-агентами.
**Дата:** 2026-06-06. **Метод:** deep web research (WebSearch + web_fetch, багатоджерельно, усіма релевантними мовами) силами 9 discovery+evaluation саб-агентів (по одному на задачу, паралельно у 2 батчах); верифікація й фінальне зведення — оркестратором. На вихід — лише текстові `.md`; нічого не завантажувалось/виконувалось на хості.

## Файли
- `_project_understanding.md` — вихід КРОКУ 1: потреба, мови (UA/RU/BG кирилиця + латиниця), 5 критеріїв, межі (комерційний-закритий → permissive), incumbents.
- `_SUMMARY.md` — підсумок оркестратора: рекомендація по кожній задачі (free/paid/під-наші-обмеження + проти incumbent), рекомендований повний стек, відкриті питання, прогалини.
- `raw/` — discovery, по 1 файлу на задачу (кандидати free+paid з посиланнями + ліцензії + кирилична нота + прогалини): `A_search_engine.md`, `B1_normalization.md`, `B2_transliteration.md`, `B3_phonetic.md`, `B4_keyboard.md`, `B5_variant_generation.md`, `C1_string_similarity.md`, `C2_name_matching.md`, `D1_dedup.md`.
- `evaluation/` — оцінка, по 1 файлу на задачу (кандидати × 5 критеріїв + рекомендація + порівняння з incumbent): `EVALUATION_A.md` … `EVALUATION_D1.md`.

## Які задачі покрито (усі 9)
- **A** Пошуковий рушій (typeahead + typo-tolerance + кирилична токенізація + ранжування) — incumbent Meilisearch.
- **B1** Нормалізація тексту — incumbent ICU.
- **B2** Транслітерація кирилиця↔латиниця uk/ru/bg — incumbent cyrtranslit.
- **B3** Фонетичне зіставлення кирилиці — incumbent НЕМАЄ (прогалина).
- **B4** Клавіатурні помилки uk/ru/bg — incumbent НЕМАЄ (прогалина).
- **B5** Генерація варіантів назви — incumbent НЕМАЄ.
- **C1** Схожість рядків — incumbent RapidFuzz.
- **C2** Крос-мовний матч імен — incumbent НЕМАЄ.
- **D1** Дедуп / record linkage — incumbent Splink.

## Нерозв'язане (одним списком)
- B3: 0 permissive фонетики для **bg**; **uk** лише G2P-примітиви → будувати; Beider-Morse не має UA/BG.
- B4: **bg** клавіатурні дані не існують у жодному інструменті → будувати БДС + Phonetic мапи (kbdlayout.info/CLDR).
- B5: генератор варіантів для **UA/BG** — збирати з примітивів; відсутні активи = BG-клавмапи + non-GPL слов'янський фонетичний кодувальник.
- B2: жодна одна бібліотека не робить усі 3 в офіційному стандарті; **BG-2009 у Python відсутній** (порт translitbg або ISO-9-ключ внутрішньо).
- C2: жоден інструмент (free/paid) не трактує **UA≠RU≠BG** окремо на рівні матчингу; ембединги не перевірені на коротких власних назвах → бенчмарк.
- Наскрізно: копілефт-пастки (Typesense/Manticore/abydos GPLv3, ParadeDB/Zingg AGPL, Elasticsearch SSPL, unidecode/python-Levenshtein/thefuzz GPL) — для кожної є permissive-альтернатива у `_SUMMARY.md`.
- Емпірична кирилична точність не виконувалась (заборона виконання у дослідженні) → рекомендований власний міні-бенчмарк на uk/ru/bg парах для фіналістів.
- Методологія пошуку: WebSearch переважно англомовний; кириличні терміни вкладено в запити, але stand-alone uk/ru/bg-інтерфейсні сесії обмежені (зафіксовано у raw-файлах).

**Підсумок:** поточний стек (Meilisearch + ICU + cyrtranslit + RapidFuzz + Splink) підтверджено як правильний і повністю permissive; реальна робота — у build-прогалинах для UA/BG, не в купівлі.

# Підсумок і рекомендований стек — зіставлення / дедуп назв

**Що це.** Зведення оркестратора по 9 задачах інструментів для каталогу коротких власних назв (сорти рослин / породи тварин) укр/рос/болг (кирилиця) + латинська транслітерація, у **закритому комерційному** продукті з self-host. Базується на 9 discovery-файлах (`raw/`) і 9 evaluation-файлах (`evaluation/`), перевірених оркестратором.
**Дата:** 2026-06-08. **Статус:** ✅ повний, з чесно названими прогалинами (особливо B3 укр/болг, B4 болг, наскрізна болгарська).

---

## Найголовніше за 30 секунд

Готового «одного інструмента» під цю задачу немає — і його не треба купувати. Реалістичне рішення — **конвеєр із permissive-блоків (MIT/BSD/Apache), усе self-host, нуль ліцензійних платежів**:

> **Пошук/UX:** Meilisearch (MIT) або OpenSearch (Apache 2.0) →
> **Канонізація:** ICU/PyICU (нормалізація) + CyrTranslit/translitua (транслітерація) →
> **Матчинг:** RapidFuzz (схожість) + власний слов'янський фонетичний шар (рос — Apache Commons Beider-Morse) + засіяні варіанти →
> **Дедуп:** Splink або string_grouper + унікальний індекс по канонічній формі.

Платні крос-мовні сервіси (Senzing, Babel Street, IBM) — потрібні лише за enterprise-масштабу/бюджету; для малої команди їх перекриває власний стек, де вони ще й слабші на болгарській.

**Три наскрізні застереження:**
1. **Болгарська — найслабша ланка** всюди (B2 Streamlined, B3 фонетика, B4 розкладка, C2). Скрізь доведеться дописувати власні дані/правила.
2. **Копілефт-пастки реальні** і часто приховані за «зручним» інструментом (Elasticsearch, Typesense, Zingg, fuzzywuzzy, Unidecode, abydos). Список — нижче.
3. **Пастка ДАНИХ ≠ коду:** код Augmentex — MIT, але вшита російська статистика помилок із KartaSlov — **CC BY-NC-SA (некомерційна)**. Брати рушій, не дані.

## Рекомендація по кожній задачі

### A — Пошуковий рушій (typeahead + typo-tolerance + ранжування)
- **Найкращий безкоштовний / під обмеження:** **Meilisearch (MIT)** — permissive без застережень, typeahead + typo-tolerance + ранжування «з коробки», найпростіший старт для малої команди, активний (v1.45+, 2026). Альтернатива за максимальну кириличну морфологію — **OpenSearch (Apache 2.0)**: рос. Snowball + болг. light stemmer + укр. `UkrainianMorfologikAnalyzer` + ICU; ціна — складніша експлуатація.
- **Найкращий платний:** окремого платного продукту з принципово кращим кириличним пошуком немає. Algolia найсильніший за UX, але **не self-host → виключений**. Якщо потрібен керований сервіс — Meilisearch Cloud / Typesense Cloud (той самий код, тариф за ресурси).
- **Уникати/перевіряти:** Elasticsearch (SSPL/AGPL/Elastic v2), RediSearch (RSAL/AGPL), Typesense/Manticore (GPL-3 — для мережевого демона окремим процесом ризик нижчий, але потрібна юридична перевірка).
- **Головний ризик:** реальний кириличний typo-tolerance документований, але **не перевірений на укр/рос/болг рядках — обов'язковий PoC.**

### B1 — Нормалізація тексту (case/Unicode folding, NFC/NFKC)
- **Найкращий (free і загалом):** **ICU / PyICU** (Unicode-3.0 / MIT) — єдиний, що закриває весь конвеєр і дає *штатний* механізм (`Transliterator`/`gennorm2`) для власного шару складання ё/е, і/и, ґ/г + UTS#39 skeleton для гомогліфів (кир. а/о/е/с = лат.). Доповнити платформними `unicodedata`/`casefold`, `ftfy` (mojibake), `text-unidecode`/`AnyAscii` (ASCII), `confusable_homoglyphs` (зафіксувати MIT-версію).
- **Платний:** немає і не потрібен — найсильніший інструмент галузі безкоштовний і permissive.
- **Ключова теза:** складання РІЗНИХ літер (ё↔е, і↔и, ґ↔г, апострофи) **жоден інструмент не робить «зі стандарту»** — це завжди власний доменний шар поверх ICU. Недооцінка цих зусиль — головний проєктний ризик кроку.
- **Уникати:** Unidecode (GPLv2+), transliterate (GPL/LGPL).

### B2 — Транслітерація кирилиця↔латиниця (укр/рос/болг)
- **Найкращий безкоштовний:** **CyrTranslit (MIT)** — двобічний, поіменно укр + рос + болг (окремі контрибʼютори для болгарської), активний (v1.2.0, лист. 2025) + **translitua (MIT)** — обов'язковий для офіційної української КМУ-2010 і рос. стандартів (ISO 9, BGN, GOST).
- **Найкращий під обмеження:** дводоріжкова permissive-архітектура — (1) **бієктивний ключ** на `iso9` (ISO 9:1995, фактично permissive PSF-style; дописати інверсію) або ICU `Cyrillic-Latin`; (2) **відображення** — translitua (укр/рос) + **власна болгарська Streamlined-таблиця**.
- **Платний:** немає.
- **Прогалини/ризики:** болгарська офіційна **Streamlined під permissive — відсутня** (готова лише в Lingua::Translit, Perl + копілефт); зворотність — лише через ISO 9 / GOST 7.79 System A (паспортні КМУ/BGN/Streamlined принципово незворотні). iuliia заархівовано (лют. 2026), transliterate без оновлень з 2018 — обидва відхилено.

### B3 — Фонетичне зіставлення (кирилиця) — ⚠️ ПРОГАЛИНА укр/болг
- **Російська (закрито):** **Apache Commons Codec `BeiderMorseEncoder` (Apache 2.0, Java)** — приймає кириличний вхід нативно; або **`fonetika` (MIT, Python)**.
- **Українська та болгарська (ВЕЛИКА прогалина):** готового перевіреного рішення **немає**. Доведено по коду: і Apache BMPM, і fonetika покривають лише російську абетку; і/ї/є/ґ відсутні у правилах; для болгарської ъ-як-голосна російські таблиці дають систематичну неточність. **Будувати власне** поверх B2-транслітерації + латинської фонетики, або розширити правила «русского Metaphone» літерами і/ї/є/ґ та болгарськими.
- **Платний:** не допомагає — гроші не знімають укр/болг прогалину.
- **Критичний ризик:** дві найповніші Beider-Morse реалізації (еталон Steve Morse / fisharebest і abydos) — **GPL-3** (успадковано від PHP-першоджерела). Єдина дозвільна дорога до того ж алгоритму — Apache Commons Codec.

### B4 — Клавіатурні помилки (ЙЦУКЕН / БДС) — ⚠️ ПРОГАЛИНА болг
- **Російська:** **Augmentex (MIT)** — готовий генератор рос. клавіатурних описок (PC+mobile ЙЦУКЕН).
- **Українська:** **nlpaug + вбудований `uk.json` (MIT)** — реальна укр. ЙЦУКЕН-мапа сусідства клавіш (перевірено вмістом файлу).
- **Болгарська (прогалина):** готових даних немає ніде — будувати вручну в **`clavier` (MIT, `from_grid`)** з геометрії БДС 5237.
- **Платний:** немає (вся категорія free).
- **Застереження:** укр і рос ЙЦУКЕН **не тотожні** (і/ї/є/ґ проти ы/э/ъ/ё) — рос-мапу не можна копіювати з `uk.json`; болгарська БДС — принципово інша розкладка.

### B5 — Генерація варіантів написання
- **Найкращий (free / під обмеження):** **оркестратор над B2+B3+B4** + власний **Norvig `edits`-генератор з кириличним алфавітом** (єдине рівноцінне покриття болгарської). Інструменти: **nlpaug (MIT)** (готова укр. клавіатура; рос/болг/OCR/spelling — власні мапи через `dict_path`/`model_path`), **Augmentex (MIT)** — лише алгоритмічні методи/власна статистика, **symspellpy (MIT)**.
- **Платний:** немає.
- **Пастка:** вшита рос. статистика Augmentex = **KartaSlov, CC BY-NC-SA (некомерційна)** — для комерційного продукту брати рушій + власні дані, не вшитий датасет. Болгарська — найбільший ручний обсяг (нуль готового покриття). abydos (GPL-3) — не потрібен.

### C1 — Схожість рядків
- **Найкращий безкоштовний / під обмеження:** **RapidFuzz (MIT)** — найшвидший (bit-parallel C++), кирилиця-безпечний на рівні code points; доповнити **textdistance (MIT)** (token/n-gram), **jellyfish (BSD-2-Clause)** як fallback, **pg_trgm** у БД-шляху (обов'язково UTF-8 locale — інакше пастка «multibyte + C locale»).
- **Платний:** є (Senzing/Data Ladder/Melissa/Informatica), але для цієї задачі **надмірні**.
- **Копілефт-пастки:** `python-Levenshtein` (GPL-2), `thefuzz`/FuzzyWuzzy (GPL-2) — заміна RapidFuzz без втрат (той самий API). Урок: ліцензію брати з репозиторію, не з агрегатора (textdistance — насправді MIT, не LGPL).

### C2 — Крос-мовний матч імен — ⚠️ ПРОГАЛИНА OSS
- **Найкращий OSS:** **немає готового** (доведена прогалина) — жодна зріла активна permissive-бібліотека не робить крос-абетковий матч як єдине ціле з доказовою слов'янською кирилицею. abydos/nama — GPL-3; HMNI — застарів 2020 + транзитивний GPL.
- **Найкращий платний:** **Senzing** — єдиний із прямим доказом української, реальним self-host/air-gapped, приватністю даних і free-tier (500 / 250k / ~1 млн PoC). Цінові якорі — enterprise-рівня (орієнтовно ~$894k/рік на 500M записів) → виправдано лише за великого масштабу.
- **Найкращий під обмеження:** **власний конвеєр B2+B3+C1** (CyrTranslit + власні фонетичні правила/jellyfish + RapidFuzz + pg_trgm) — реалістичніший за платне для малої команди й дає контроль над болгарською/українською, де вендори слабкі.
- **Ризик:** болгарська — жоден платний вендор не називає її поіменно (Senzing → «Generic/East Slavic»).

### D1 — Дедуп / зв'язування записів
- **Найкращий безкоштовний:** **Splink (MIT)** як дедуп-двигун (масштаб DuckDB→Spark, self-host); під короткі назви практичний стек — **string_grouper (MIT, n-gram TF-IDF) + RapidFuzz + транслітерація**; **recordlinkage (BSD-3)** — сильна третя опція.
- **Найкращий платний:** **Senzing** (єдиний комерційний зі справжнім self-host + безкоштовним пілотом + не-латинськими алгоритмами імен). Застереження: модель під персони/організації, а кейс — сорти/породи → пілот обов'язковий.
- **Уникати (копілефт):** **Zingg — AGPL-3.0** (головний прапор; мережеве застереження → для закритого продукту потрібна комерційна ліцензія); fuzzywuzzy/thefuzz (GPL-2); FEBRL (ANUOS); Talend Open Studio (безкоштовний DQ припинено 31.01.2024). dedupe — сам MIT, але аудитувати транзитивні залежності.

## Рекомендований повний стек (архітектура конвеєра)

Один наскрізний потік, усе permissive + self-host:

1. **Прийом і канонізація запису (B1 + B2).** ICU/PyICU нормалізує (NFC, casefold, прибирання діакритики/пунктуації) + власний шар складання кириличних варіантів (ё/е, і/и, ґ/г). Паралельно CyrTranslit/translitua/iso9 дають **латинський ключ** і **транслітераційний ключ**. На виході — канонічна форма + 2 ключі.
2. **Засів варіантів (B5 поверх B3+B4).** Для канонічної назви заздалегідь генеруються правдоподібні написання (клавіатурні — nlpaug `uk.json`/Augmentex/clavier; фонетичні — Apache BMPM рос. + власні укр/болг; орфо/трансліт — edits-генератор). Індексуються як синоніми.
3. **Пошук і підказка (A).** Meilisearch/OpenSearch віддає typeahead із typo-tolerance, ранжуванням і boosting популярних записів поверх канонічних форм + засіяних варіантів.
4. **Рішення «той самий запис?» (C1 → C2).** RapidFuzz + token/n-gram + слов'янська фонетика дають числову оцінку схожості (= саморобний крос-скрипт матч замість платного C2).
5. **Чистота каталогу (D1).** Splink / string_grouper для пакетного пошуку дублів + **унікальний індекс по канонічній формі** у БД як апаратна гарантія «без дублів».

**Платформне рішення впливає на B3:** Apache Commons Beider-Morse — Java; fonetika — Python. Якщо стек Python — фонетику для рос. брати з fonetika, для укр/болг будувати власне.

- **AGPL / SSPL / source-available (найвищий ризик):** Elasticsearch (SSPL/AGPLv3/Elastic v2), RediSearch/Redis 8 (RSAL/AGPL), **Zingg (AGPL-3.0)**, Quickwit (історично AGPL).
- **GPL-2/3 (копілефт):** Typesense / Manticore / Sphinx (GPL — нижчий ризик як окремий мережевий демон, але юридична перевірка обов'язкова), **python-Levenshtein / thefuzz / fuzzywuzzy (GPL-2)**, **Unidecode (GPLv2+)**, **abydos і еталонний Beider-Morse (GPL-3)**, transliterate (GPL/LGPL).

- **Безпечні permissive-заміни напохваті:** RapidFuzz замість python-Levenshtein/thefuzz; OpenSearch замість Elasticsearch; text-unidecode/AnyAscii замість Unidecode; Apache Commons Codec замість GPL-Beider-Morse.

## Чесні прогалини

- **B3 (фонетика) — українська та болгарська:** готового немає, ~2/3 задачі — власна розробка. Російська закрита (Apache BMPM / fonetika).
- **B4 (клавіатура) — болгарська (БДС):** немає готових даних; будувати вручну (обмежений разовий обсяг — одна розкладка). Рос. і укр. закриті.
- **B2 (транслітерація) — болгарська Streamlined під permissive:** немає; писати власну малу таблицю. Зворотність — лише через ISO 9.
- **C2 (крос-мовний матч) — OSS:** немає зрілого permissive-рішення з доказовою кирилицею; будувати власне або платити Senzing.
- **Наскрізна болгарська:** найслабша мова в B2, B3, B4, C2 — закладати додатковий бюджет саме на неї.
- **Бенчмарки:** опублікованих тестів якості саме на коротких кириличних власних назвах **немає для жодного інструмента** — придатність оцінено через мовно-нейтральність метрик і код, а не готові тести. **Емпіричний PoC на власних даних обов'язковий.**

## Відкриті питання

1. **Платформа (Python vs JVM)** — визначає вибір фонетики B3 (Apache Commons = Java; fonetika = Python) і зручність решти стеку.
2. **Юридична перевірка** GPL/AGPL/SSPL під конкретну архітектуру (окремий демон vs лінкування в код): для Typesense/Manticore/Sphinx як мережевих сервісів ризик нижчий, але потребує підтвердження юристом.
3. **Масштаб для C2/D1:** чи виправданий Senzing — залежить від обсягу записів; за невеликого/середнього — власний стек дешевший і гнучкіший на болгарській.
4. **Болгарські дані:** хто й коли збере болгарські фонетичні правила, БДС-розкладку та Streamlined-таблицю (наскрізна прогалина).

## Наступні кроки

- Підтвердити пороги схожості й boosting на цих даних.
- Прийняти рішення «власний стек vs Senzing» для C2/D1 за результатами PoC і оцінки масштабу.

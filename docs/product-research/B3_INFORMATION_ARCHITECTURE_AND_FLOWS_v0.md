## §2. Мінімальна модель сутностей `нова-дизайн-пропозиція`

Це єдиний новий дизайн у B3. Він авторизований оператором цією сесією й сумісний із точкою стику `DB_SEED_AND_DATA-MODEL_SPEC_v1_2.md §7.7 · виведено-з-PRD`, яка прямо фіксує: «Повна модель об'єкта — у продуктовій спеці; тут фіксуємо лише зв'язок» — тобто DB_SEED навмисно НЕ визначає об'єкт, лишаючи це продуктовому шару (саме його B3 і заповнює, не суперечачи каталогу). Критерій усієї моделі — дизайн-північ §0: мінімум полів, максимум смарт-дефолтів, аби «завести об'єкт і почати лог» коштувало якнайменше тапів.

**ПРОСТІР — легкий контейнер** (`нова-дизайн-пропозиція`, узгоджено `OverGarden_MVP_PRD_v0.md §2 S6 · виведено-з-PRD`). Поля: **назва** (вільний текст; smart-default на кшталт «Мій сад»; обов'язкове-але-задефолчене, тобто користувач не мусить нічого вводити); **тип-чип** (опційний легкий набір грядка / теплиця / балкон / сад / поле / інше — лише для групування, не обов'язковий); **видимість локації** — 3 рівні точно / регіон / приховано, дефолт **регіон** (`OverGarden_MVP_PRD_v0.md §5 AC-S9b · вирішено-каноном`), що задається на просторі й **успадковується об'єктами**. Грубий регіон — похідне, обчислюється **тільки server-side**; точні координати **ніколи не передаються на клієнт** (`ENTRY_DATA_AND_RANKABILITY_SPEC_v0.md §5 · вирішено-каноном`; `AC-S9b`). **[ADD 2026-06-21]** Простір також несе **ЖУРНАЛ ПРОСТОРУ** — стрічку наративних записів-простору (історій на рівні саду), що можуть @-тегати ≥1 об'єкт ЦЬОГО простору. Раніше простір був лише контейнером-списком; запис-простору — рішення оператора 2026-06-21 (`нова-дизайн-пропозиція`, узгоджено `OverGarden_MVP_PRD_v0.md §2 S6` ред.2026-06-21). Поля простору (назва / тип-чип / видимість-локації) вище — PRESERVE; замок локації не чіпано.

**ОБ'ЄКТ — аналог авто Drive2, серце моделі** (`нова-дизайн-пропозиція`; референс `DRIVE2_CANON_v1.md §3 · вирішено-каноном`). Поля: **`catalog_item`** — FK→`CatalogItem` через tap-select / typeahead або «Unknown»-fallback (`OverGarden_MVP_PRD_v0.md §2 S7 · виведено-з-PRD`; `DB_SEED_AND_DATA-MODEL_SPEC_v1_2.md §7.7 · виведено-з-PRD`); це соцграф-ключ і **єдине напів-обов'язкове поле**, та й воно має Unknown-fallback, тож не блокує. **Прізвисько** — опційне; smart-default = канонічна назва сорту або «Об'єкт N». **Простір** — FK→Space; smart-default = останній-вжитий; якщо жодного простору ще немає — авто-створюється дефолтний (щоб об'єкт ніколи не «висів» без контейнера). **Обкладинка-фото** — опційна (`OverGarden_MVP_PRD_v0.md §2 S4 · виведено-з-PRD`). **Дата старту/посадки** — опційна, дефолт сьогодні, backdatable (`OverGarden_MVP_PRD_v0.md §2 S2 · виведено-з-PRD`). **Override видимості локації** — опційний, успадковує простір (`AC-S9b · вирішено-каноном`).

**ЖУРНАЛ [REPLACE 2026-06-21]** = зворотньо-хронологічна стрічка наративних ЗАПИСів. ## §3. Карта сутність↔поверхня (біекція, нуль сиріт в обидва боки)

Кожна сутність має рівно одну первинну поверхню, і кожна поверхня обслуговує рівно одну сутність — перевірка біекції тримається в обидва боки.

Сутність **Користувач** → поверхня **дім / список Просторів** (коренева зона застосунку). Сутність **Простір** → поверхня **список Об'єктів цього простору + ЖУРНАЛ ПРОСТОРУ** (стрічка записів-простору + affordance «нова історія» + @-typeahead по власних об'єктах) `[ADD 2026-06-21]`. Сутність **Об'єкт** → поверхня **екран об'єкта** (паспорт-картка + стрічка-журнал + affordance «новий запис» `[REPLACE 2026-06-21]`). Сутність **Запис** → поверхня **деталь у стрічці журналу** + **публічна сторінка-запис** (авторитет `ENTRY_DATA_AND_RANKABILITY_SPEC_v0.md §3 · виведено-з-PRD`; `B5_SEO_CONTENT_ARCHITECTURE_v2.md §2 · виведено-з-PRD`). Сутність **`CatalogItem`** → поверхня **публічна сторінка-сорт як агрегація** (авторитет `ENTRY_DATA_AND_RANKABILITY_SPEC_v0.md §3 б · виведено-з-PRD`; `B5_SEO_CONTENT_ARCHITECTURE_v2.md §2 · виведено-з-PRD`), досяжна з лінка сорту на екрані об'єкта. Сутність **Wishlist** → поверхня **окрема полиця** (`OverGarden_MVP_PRD_v0.md §2 S12 · виведено-з-PRD`). **[ADD 2026-06-21 — крос-юзерні поверхні]** Сутність **Користувач** → ДОДАТКОВО публічна **сторінка-профіль @-хендла** (псевдонімна; `PRD §2 S16 · виведено-з-PRD`). Нова поверхня **вхідні запити-теги (claim-inbox)** ← `Edge` у `state=proposed` (`PRD §2 S15 · виведено-з-PRD`). Нова поверхня **граф-родовід (lineage view)** ← провенанс-`Edge`/`CatalogItem`, досяжна зі сторінки-сорту й екрана об'єкта (`PRD §2 S18 · виведено-з-PRD`). **Провенанс-блок** на екрані об'єкта й публічній сторінці-сорті ← confirmed provenance/reference `Edge`, рендер сорт-медіаційний (`PRD §2 S14/S18`; `ENTRY §3б`; `CROSS_USER_TRUST §3 · виведено-з-PRD`).

Зворотний бік (нуль поверхонь-сиріт): дім ← Користувач; список Об'єктів ← Простір; **журнал простору ← Простір (записи-простору) `[ADD 2026-06-21]`**; екран об'єкта ← Об'єкт; деталь-у-стрічці + публічна сторінка-запис ← Запис; сторінка-сорт ← `CatalogItem`; полиця ← Wishlist. Поверхонь без сутності-власника немає; сутностей без поверхні немає. **[ADD 2026-06-21]** Сутність ЗАПИС: запис-об'єкта живе в журналі об'єкта, запис-простору — в журналі простору (нуль сиріт відновлено для space-scope). **[ADD 2026-06-21]** Крос-юзерні поверхні: claim-inbox ← `Edge(proposed)`; граф-родовід ← провенанс-`Edge`/`CatalogItem`; профіль-@-хендла ← `User` (публічний бік); провенанс-блок ← confirmed `Edge`. Нуль сиріт тримається для крос-юзерного шару.

## §4. Скелет IA (топ-рівневі зони)

Три топ-рівневі зони. **(А) Моє** — особистий робочий вид користувача: дім → Простори → Об'єкти → Журнали; саме тут живе щоденне журналювання й вкладеність **ПРОСТІР → ОБ'ЄКТ → ЖУРНАЛ** (`OverGarden_MVP_PRD_v0.md §2 S6 · виведено-з-PRD`). «Особистий» тут стосується лише навігації («це мій робочий вид»), НЕ видимості контенту — контент публічний-за-замовчуванням (§5 паркан 2). **(Б) Публічне** — сторінки-записи й сторінки-сорти як агрегації; користувач доходить сюди не окремою дією «опублікувати», а через **шов publish**: рутинний лог публікує запис одразу (§5 паркан 3), і той самий запис стає вузлом публічного шару, чию таксономію тримають `ENTRY §3` / `B5 §2/§4` (B3 її не переробляє). **(В) Wishlist** — окрема полиця «спробувати наступного сезону», не логувальний примітив (`OverGarden_MVP_PRD_v0.md §2 S12 · виведено-з-PRD`).

Шлях до публічного шару **[REVISED 2026-06-21]**: користувач веде наративний запис (об'єкта або простору) у зоні «Моє» → Запис публічний-за-замовчуванням (`AC-S9a · вирішено-каноном`) → публічна сторінка-запис. Членство в агрегації сторінки-сорту = **сорт home-об'єкта** (контекст-якір, запис-об'єкта) **∪ сорти @-тегованих об'єктів** (запис-простору) (`ENTRY §3a/§3б` ред.2026-06-21). Таксономію сторінок B3 не переробляє — посилається. Лінк сорту на екрані об'єкта — місток із «Моє» в «Публічне».

## §5. Ядрові флоу (структура, не пікселі)

Кожен флоу — нумерована послідовність кроків; під кроком, де він несе фрикційну техніку, стоїть важіль + статус-тег у точці його дії. Флоу не вводять жодної фічі понад S1–S13.

**Флоу 1 — Перший запуск (aha-шлях).** Мета **[REPLACE 2026-06-21]** — від нуля до першого НАРАТИВНОГО запису якнайшвидше; це й є момент «aha» (не «приєднався до мережі», а «зафіксував перший запис і відчув миттєву віддачу» — `BEACHHEAD_GTM_v0.md р.176 · виведено-з-PRD`).
1. Старт → авто-створюється дефолтний Простір зі smart-default назвою «Мій сад» (важіль: усунення-порожнього-стану; `нова-дизайн-пропозиція`, узгоджено `S6`).
2. Завести перший Об'єкт: tap-select сорту через typeahead або «Unknown» → готово; прізвисько/фото/дата задефолчені (важіль: тертя-входу/perceived-effort; `OverGarden_MVP_PRD_v0.md §2 S7 · виведено-з-PRD`).
3. Перший наративний запис (title+body, голос/фото-старт) з картки об'єкта **[REPLACE 2026-06-21]** (важіль: активація; `OverGarden_MVP_PRD_v0.md §5 AC-S1 · виведено-з-PRD` ред.2026-06-21).

## §6. Критичні паркани (голосно; не порушуються)

**Паркан 1 — batch-log ПОЗА v0.** Гуртовий лог обходу позначено **deferred-post-MVP** (рішення оператора цієї сесії; `нова-дизайн-пропозиція` у статусі deferral). **Паркан 2 — НЕМАЄ перемикача приватності КОНТЕНТУ.** У v0 його нема: приватних записів немає, контент публічний-за-замовчуванням (`OverGarden_MVP_PRD_v0.md §5 AC-S9a · вирішено-каноном`; `§11.2 п.21 · вирішено-каноном`). Це **дві ортогональні осі** (контент публічний-за-замовчуванням × локація-селектор), не одна (`OverGarden_MVP_PRD_v0.md §2 S9 · вирішено-каноном`). B3 не конструює жодного UI «публічно/приватно» для контенту.

**Паркан 3 [REVISED 2026-06-21] — публічно-за-замовчуванням, без гейта.** Наративний запис публікується за замовчуванням на save (`AC-S9a · вирішено-каноном`), без гейта-публікації; «Чернетка» (`S6`) — опційна вторинна дія, не обов'язковий крок (Флоу 10). *(Прибрано «однотап»-формулювання — примітив наративний.)* **[ADD 2026-06-22]** Уточнення: «без гейта» = немає PER-ENTRY публікаційного гейта. ПЕРША публікація несе ОДНОРАЗОВЕ розкриття (AC-S9c, Флоу 21) — це не recurring-гейт, а одноразовий легальний момент, вбудований у дію save; після нього — рівно «без гейта».

**Паркан 4 — p_pub (готовність публікувати) — живий пост-лонч сигнал, не попис-перемикач.** У v0 p_pub міряється живим (location-setting + чи лишають запис публічним), не питанням UI (`ENTRY_DATA_AND_RANKABILITY_SPEC_v0.md §1 а · виведено-з-PRD`). B3 не конструює UI «публічно/приватно» й не бандлить публікацію з журналюванням.

**Паркан 5 — 4 поведінкові інваріанти роздільні.** Інтерес ≠ журналити (p_journal) ≠ платити (p_pay) ≠ публікувати (p_pub) — чотири незалежні поведінки/сигнали (`KILL_CRITERIA_PREREG_v2.md §0 · вирішено-каноном`). Журналювання й публікація — різні кроки/сигнали (Флоу 2 vs шов publish §4), не бандль.

**Паркан 6 — жодної цінової / платіжної поверхні.** p_pay поза MVP (`OverGarden_MVP_PRD_v0.md §11.2 · вирішено-каноном`: тарифи / freemium — OUT). B3 не вводить жодного екрана ціни, тарифу чи оплати.

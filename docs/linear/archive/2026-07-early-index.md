## OVE-78 — Production catalog proof seed: operator seeds the approved proof set into the selected non-local environment

- Status: Done · completed 2026-07-01 · created 2026-06-30
- Project: SDD Slice 12 — Full Catalog Import Rollout · Priority High · 3 points
- Branch: `yehordesign/ove-78-production-catalog-proof-seed-operator-seeds-the-approved`

## User behavior

The operator deliberately seeds the approved catalog proof set into staging or production, then verifies through the real app path that the proof items are available without exposing source-only fields or confusing deployed-code state with database state.

This is the bridge from OVE-69 local proof to real non-local catalog availability.

## Invariants

* No staging/production mutation without explicit environment selection and `--allow-non-local-mutation`.
* No secrets, database URLs, env values, invite/reset URLs, cookies, emails, source-record rows, raw payload hashes, user identifiers, media keys, exact coordinates, IPs, user agents, or referrers in evidence.
* The proof set is not a claim that the full catalog has been imported.

## Target behavior

* Operator selects `staging`, `preview`, or `production` explicitly.
* Seed command runs only the approved proof set: `Ботсадівський`, `Solanum lycopersicum L.` / `помідор` / `домат`, `Карпатська бджола`, `Садово 1`, and `Red Cherry tomato`.
* Real `/garden` smoke verifies readback for every proof item.
* Evidence records commit SHA, environment, app URL, idempotency, duplicate absence, and leak-check status.

## Non-goals

* No bulk/full catalog import. No new source ingestion. No automatic production seed on deploy. No destructive database reset.

## Acceptance criteria

* Redacted evidence proves proof-set availability in the selected non-local environment.
* Evidence distinguishes deployed code, local proof DB, staging DB, and production DB state.
* Re-running the proof does not duplicate product-visible catalog suggestions.
* `docs/INFRASTRUCTURE_REGISTRY.md` and `docs/CATALOG_SEED_ROLLOUT_PROOF.md` reflect the environment seed state.

## SDD Slice Test

Valid vertical slice: explicit non-local seed intent → controlled DB mutation → real app readback → idempotency and leak proof → environment status docs.

## OVE-79 — Full catalog import readiness gate: operator approves source versions, export paths, licenses, and import waves before bulk ingestion

- Status: Done · completed 2026-07-01 · created 2026-06-30
- Project: SDD Slice 12 — Full Catalog Import Rollout · Priority High · 5 points
- Branch: `yehordesign/ove-79-full-catalog-import-readiness-gate-operator-approves-source`

## User behavior

Before OverGarden imports full catalog volumes, the operator can review one machine-checkable import-wave manifest that says which source/version/export path may be imported, which fields are raw-only, which fields may reach product projection, and which sources are still blocked.

This turns the founder goal "import everything" into a controlled source-by-source rollout plan instead of an unsafe bulk dump.

## Invariants

* External endpoints, export availability, and license terms may drift; do not trust old proof for full-volume import.
* `USE-WITH-CONDITIONS`, `INTERNAL-VALIDATION-ONLY`, and `REJECT` sources cannot feed product projection without a fresh explicit gate.
* External occurrence/distribution coordinates remain raw/source-only unless a later ADR and SDD slice explicitly promote safe aggregate projections.
* Vendor/marketplace scraping remains rejected unless there is a partner feed, official API contract, or written permission.

## Target behavior

* The verifier rechecks all source families needed for full import: UA State Register, CoL/ChecklistBank, WFO, GBIF Backbone, EPPO, Wikidata, GRIN/NPGS, VBO, BG/EU official variety sources, DAD-IS/EFABIS, EURISCO, Genesys, EOL/iNaturalist if considered for aliases, and vendor/marketplace paths.
* The output groups sources into import waves: `raw_quarantine_allowed`, `product_projection_allowed`, `operator_review_required`, `legal_blocked`, `parser_blocked`, `rejected`.
* The manifest records exact source version/export URL or access method, license, attribution requirement, source-only fields, volume estimate, parser risk, and next issue dependency.

## Acceptance criteria

* A checked-in manifest/update names every source family and its current full-import verdict.
* Each verdict says whether full raw/quarantine import is allowed and whether product projection is allowed.
* Blocked/conditional sources have concrete unblocking evidence requirements, not vague notes.
* Later Linear import issues link to this gate.

## SDD Slice Test

Allowed gate slice: operator-visible decision output → machine-checkable manifest → docs update → later import waves blocked unless this gate passes.

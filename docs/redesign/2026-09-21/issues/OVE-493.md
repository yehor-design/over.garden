## Acceptance criteria

1. Use the same author/context/content anatomy as feed; show a compact coherent action row for supported reaction, comment, save and share functions. Do not introduce unsupported reaction types.
2. Share uses native share when supported with reliable copy-link fallback and accessible success/failure feedback; canonical permalink never includes transient auth/filter tracking state.
3. Comments have explicit reply target, pending/error state, keyboard reachability and meaningful deleted/moderated states. Guest actions preserve intent through sign-in within current constraints.
4. Prevent duplicate submissions and reconcile actual server response; an optimistic appearance is never accepted as server success. Preserve server-authoritative interactions and no-hydration gates.
5. Consolidate related entries into one relevant section and distinguish same-object history from unrelated recommendations. Maintain back-to-source context without changing canonical address.
6. Media, author links, object link and menu all have distinct targets. Long text and portrait photos remain readable at 320px, zoom and slow load.

## Proof

Controlled guest/member comment, reaction, save and share tests including network failure and double press; keyboard traversal and read-only static HTML proof. Compare same content feed/detail and verify one related section.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof. Never publish test content to production without the applicable authorization.

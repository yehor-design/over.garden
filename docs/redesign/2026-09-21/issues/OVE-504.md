## Acceptance criteria

1. Use consistent focused layouts for sign-in, sign-up, reset-password and auth help, with clear mode changes and inline recoverable errors.
2. Preserve validated same-origin return intent for writing, commenting, saving and community contribution. Reject open redirects and unauthorized object IDs server-side.
3. Allow password-manager/autofill/paste; accessible authentication never requires memorization puzzles introduced by the redesign.
4. Explain when a full-page transition cannot preserve transient writing; use in-memory recovery only where viable and no IndexedDB/local draft workaround.
5. Expired links, already authenticated users, provider/network failure and pending submissions have distinct states. Existing security and anti-enumeration behavior stays intact.
6. Locale choice persists according to shipped ADR-0029/current language contract rather than flipping when a canonical unprefixed link opens.

## Proof

Guest action→auth→target for object/space/community/bookmark, invalid return URL, expired reset and keyboard/autofill scenarios; verify no unauthorized destination and no durable browser journal data.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof. Never publish test content to production without the applicable authorization.

## Outcome

My garden is a place to find owned spaces/objects and write again, not a dashboard mixing every editor and setting.

## Acceptance criteria

1. Prioritize collection search, spaces/objects and visible New entry. Move full editors, settings, provenance and destructive actions to dedicated contexts defined in IA.
2. Support useful recent/all views with real sort semantics, object identity, space context and direct contextual Write action. Large collections use bounded loading/pagination and preserve query/back position.
3. Treat 0 destinations as setup with relevant Thiings illustration and clear first action; 1 destination stays simple; 100/1000 objects remain searchable without scanning cards.
4. Replace inferred needs-attention health claims with factual last-entry recency and optional neutral reminder wording. Do not diagnose plant status from logging frequency.
5. Keep all workspace reads settled independently. Failed section shows retry and does not hide other owned collections or claim empty.
6. Owned pages consistently retain My garden active navigation. Species/reference links are secondary and explicitly labeled.

## Proof

Capture 0/1/100/1000 object views and query→object→back, contextual Write counts and partial failure. Keyboard/accessibility checks use ordinary member as well as owner.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof.

## Acceptance criteria

 1. Define primitive and semantic color, spacing, typography, radius, border, elevation and motion tokens. Keep existing fonts unless the canon explicitly changes them; do not introduce another visual theme for owner screens.
 2. Build or adapt button, icon button, input, field error, select, tabs, menu, dialog, sheet, toast/status, skeleton and empty-state primitives with default/hover/focus/pressed/disabled/pending/error states.
 3. Default to restrained surfaces, author-first text hierarchy and consistent separators. Give content photos their own sizing policy; no universal oversized 4:3 cover.
 4. Meet text contrast 4.5:1 normal/3:1 large and meaningful non-text contrast 3:1; focus stays visible and unobscured. Controls meet WCAG 2.2 target sizing or documented exceptions; aim 44px for primary touch actions.
 5. Respect reduced motion, text zoom and forced colors. Decorative motion never communicates the only state.
 6. Update mechanical design gates to enforce the new canon without treating passing token checks as proof of usability. Publish a component specimen route or existing equivalent for visual verification.
 7. Inventory Lucide, Radix icon assets, react-icons, bespoke functional SVGs and emoji used as controls; map every semantic action to one Phosphor glyph. Keep brand marks, favicons and user media as explicit non-interface-icon exceptions.
 8. Create a small typed icon entry point with consistent weight and size tokens; selected states may use a documented fill variation of the same family, never a second family.
 9. Use server-compatible imports for static/server components and narrow imports so the full icon collection is not bundled into guest chrome. Verify package API against its installed official docs.
10. Provide accessible names on icon-only controls; decorative icons are hidden from AT. Tooltips supplement labels, not replace them. Meaning cannot depend solely on glyph or color.
11. Remove unused old icon dependencies after all consumers migrate; prevent reintroduction through an appropriate import/source gate.
12. Inspect desktop/mobile navigation, dialogs, rich editor, social actions, validation, owner tables and loading states. Thiings art is illustration, not a substitute icon family.

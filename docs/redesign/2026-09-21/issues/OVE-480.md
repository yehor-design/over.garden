## Acceptance criteria

1. Seed guest, ordinary member, sealed owner and expired-session fixtures; 0/1/3/20 spaces and 0/1/100/1000 objects, duplicate names in distinct spaces, unassigned objects and long UK/BG/RU names.
2. Create text-only, portrait/landscape/multiple photo, mixed-script, long entry, deleted destination, empty list, failing section and realistic media-weight fixtures. Keep real production personal content out of fixtures.
3. Configure automated coverage for relevant WCAG 2.2 AA rules including wcag22aa where supported, and record tool/rule versions. Automated pass is not conformance certification.
4. Provide reusable keyboard, focus return, live status and pending/error assertions; include 320px, 390px, 768px, 1280px and 1920px plus 200% text/400% zoom checks where relevant.
5. Register every new browser spec in the actual browser gate. Document screen-reader/manual steps and which cannot be automated; no dormant spec outside CI.
6. Retain baseline reproductions for wrong global CTA, first-space selection and filter Close being named Reset all.

## Proof

Run the fixture setup and representative gate from a clean checkout, attach command outputs and coverage matrix. Prove at least one baseline regression test fails before its corresponding UI correction.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof. Never publish test content to production without the applicable authorization.

## Acceptance criteria

1. Progress from living-subject type/name to optional supported catalogue identification and space selection, then concise editable summary; derive exact required fields from current schema and avoid adding arbitrary mandatory questions.
2. Show plant/animal-appropriate labels in every locale. A catalogue result describes a shared organism, not an owned specimen; unresolved identity follows existing permissive creation rules.
3. Offer all owned spaces, No space when supported and Create space inline. Preserve selected species and user text through step changes and nested space creation.
4. When launched from catalogue, show existing owned matches before offering another specimen so users can write to an existing tomato without duplicating it.
5. Use stable-ID results and acknowledge object creation separately from first-entry publication according to task 01 transaction decision. Failed publish must never masquerade as saved content.
6. Do not impose this wizard on contextual or global entry writing to an existing destination. Keep optional provenance and advanced attributes outside the main required path.

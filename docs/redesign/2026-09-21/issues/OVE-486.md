## Acceptance criteria

1. Contextual open preselects exact object/space visibly in one activation. Global open with multiple destinations immediately exposes picker; selecting a recent result focuses writing without another Continue step.
2. Keep destination and public visibility visible alongside editable observation date; handle timezone boundaries deliberately. Required content follows server contract, not an invented mandatory title/cover step.
3. Desktop uses accessible focused dialog or routed editor; mobile uses full-height reachable writing surface. Direct links have a working full-page fallback. Returning close restores launch context.
4. Changing destination preserves text/date/media. Space observations write to space itself; object entries may aggregate into its parent without duplicate publication.
5. First-publication disclosure appears only when required and uses corrected copy. Existing users do not receive recurring confirmation merely because the destination UI is unclear.
6. Keep Lexical/JournalDocumentV1 rich capability behind discoverable optional controls. No durable browser drafts, offline queue or claim of autosave.
7. Pending/success/failure messages reflect actual acknowledgment. Double activation yields one durable entry; timeout ambiguity uses existing idempotency/readback semantics. Stale authorization preserves in-memory input and explains recovery.

## Proof

End-to-end seeded publish to space and each of two same-name objects, destination switch after typing, session expiry, removed destination, timeout/double-click and exact permalink. Record navigation counts separately from typing, media actions and Publish.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof.

## Acceptance criteria

1. Use one max-width grid centered as a group with outer margins; do not pin rails to opposite viewport edges. Document chosen dimensions as OverGarden decisions rather than reverse-engineered [vc.ru](<http://vc.ru>) facts.
2. At wide desktop show left navigation, main content and useful right context; collapse supporting context before sacrificing readable main width. At narrow widths use one content column and reachable primary navigation.
3. Give each surface one active navigation destination. Owned object/space pages highlight My garden rather than Catalogue. Collapse duplicate rail/account/personal tabs into clear primary and utility groups.
4. Keep New entry a consistent creation affordance with a safe routed destination until the shared composer lands; never send it to add-object as a substitute.
5. Right rail is page-specific: context about current object/community or meaningful related discovery. Hide when nothing relevant exists; no repeated generic welcome/info card.
6. Implement landmarks, skip link, one main, heading hierarchy and keyboard order. Sticky navigation may not obscure focused controls or the mobile keyboard; no nested accidental vertical scrollbar in horizontal strips.
7. Keep late session/locale updates outside unstable ancestor context and preserve static public bytes. Coordinate with <issue id="d4eaed85-8276-44c6-923e-67c705b2de38" href="https://linear.app/overgarden/issue/OVE-468/a-guest-on-a-reading-page-downloads-337-kb-of-script-the-chromes">OVE-468</issue> lazy chrome; first click must work before/after enhancement.

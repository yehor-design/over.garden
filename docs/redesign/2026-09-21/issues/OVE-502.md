## Acceptance criteria

1. Distinguish saved reading entries from wanted organisms using explicit names and shared utility navigation. Do not merge distinct entities into an ambiguous bucket.
2. Empty shelves show one relevant browse action and optional restrained Thiings art, without unusable filter chrome.
3. Populated shelves support existing sorting/filtering with preserved back position, shared post/reference cards and exact removal feedback.
4. Guest links lead to appropriate sign-in intent; owner-only access and ordinary-member access use existing authorization.
5. Handle deleted/unavailable saved items and failed unsave without silently removing successful state or throwing away the whole shelf.
6. Remove duplicate personal navigation patterns replaced by the shell.

## Proof

0/1/many saved entities, saved item→detail→back, keyboard unsave failure and expired session; assert state matches backend and names are consistent in all locales.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof.

## Acceptance criteria

1. One H1 and concise object/parent identity precede timeline and contextual Write. Keep tabs/sections purposeful: history, details/settings, provenance only as needed.
2. Separate public passport link from Catalogue link and garden breadcrumb; the gardener always knows whether they are viewing their specimen or a shared organism.
3. Move delete, catalogue re-identification and lineage reassignment into clearly named secondary workflows. Confirmation names current and proposed entities and preserves server validation.
4. Plant/animal terminology follows actual kind. Do not allow an apparent unrelated bee/tomato option to pass without validating the actual relation rules; distinguish observed UI ambiguity from a proven mutation bug.
5. Use neutral logging recency rather than health diagnoses. Keep reminders contextual and never a blocking step before writing.
6. Preserve settled reads, loading/error boundaries, permission changes and view/back position. Old direct links continue to work.

## Proof

Compare main timeline against settings/provenance views using plant/animal and long histories. Test ambiguous relation choices and destructive cancel in fixtures; prove no unauthorized mutation and no multiple top-level H1.

Attach changed-file/behavior summary, exact tested SHA and relevant automated output. Use ordinary member as well as owner where roles apply; verify UK/BG/RU, narrow/wide layouts, empty/populated and pending/error/retry states. Public changes require canonical/static/no-JS proof; workspace changes require hard-load bounded failure proof. Mutations require actual server outcome. Register browser tests in the real gate. Manual accessibility evidence cannot be replaced by an axe score. Follow repository PR/CI/release closeout; local success alone is not production proof. Never publish test content to production without the applicable authorization.

## 3. The 32 `[...missing]` catch-alls

Every directory in `(default)` mounts `[...missing]/page.tsx`, a one-line `export { default } from "@/app/missing-route"` (all 32 files are identical; `src/app/missing-route.test.tsx:21-33` fails if a family lacks one). The reason is routing, not content: a path under a known first segment that no page serves must not fall through to `[locale]/[profileHandle]` with the section name as its locale (missing-route.tsx:3-8). `MissingRoute` calls `notFound()`, which renders `(default)/not-found.tsx` (a generic title and a link home; it reads the interface locale inside its own Suspense) with Next's `noindex` — **but at HTTP 200**, because the root `(default)/loading.tsx` has already streamed the shell before the page runs (missing-route.tsx:8-11, ADR-0029 D3 calls this the "`200` carrying a `noindex` apology"). A real status can only be chosen in the proxy, which decides from the shape of the path before anything renders:

1. First segment not in `ROOT_ROUTE_SEGMENTS` → 404 document (`isUnknownRootPath`, proxy.ts:905-918; root-route-segments.ts:15-54, 202-219).
2. A bare section root with no page — `/account`, `/answers`, `/auth`, `/breed`, `/col`, `/eppo`, `/gbif`, `/guides`, `/id`, `/journal`, `/lineage`, `/markets`, `/sources`, `/topics`, `/variety`, `/wikidata` — → 404 document (`isSectionRootWithoutIndex`, proxy.ts:944-966; root-route-segments.ts:98-116). `/species` is taken earlier by the legacy catalogue door and answers 308 `/catalog` (proxy.ts:885-903). A bare root never reaches a catch-all anyway: `[...missing]` needs at least one segment, so the bare path would fall to `[locale]/page.tsx`.
3. A deeper path under an address prefix that can never be an address (`/lineage/objects/`, `/communities/` except `…/discussions/{id}`, `/species/` except `{s}/{f}` and `{s}/register`, `/variety/`, `/journal/`, `/topics/`, `/breed/`, `/@`) → 404 document (`unservableAddressNamespace`, match-address-path.ts:219-270; prefixes in src/lib/address/address-contract.generated.ts:112-124).
4. `/bg|ru/{section}` that the prefixed tree lacks → 404 document (`isUnknownLocalizedPath`).
5. Retired namespaces (`/admin/**`, `/join`, `/health`, `/garden/pilot-*`, `/garden/catalog/**` except queue and sources), the `/q` twin segment named from outside, and the skeleton namespace outside a loopback dev/test runtime → **empty-body** 404 (`getHardNotFoundResponse`, proxy.ts:139-147; used at :816-846).

Rules 2–4 run for document navigations only; an RSC or prefetch request for the same shape reaches the App Router. Rules 1 and 5 run for every request.

Since ADR-0032 D1 the proxy also rewrites every GET/HEAD/POST of a `localized-link` address into `[locale]` (proxy.ts:682-754). For the families whose policy is a **prefix** (`/answers/`, `/blog/`, `/guides/`, `/communities/`, `/topics/`, `/journal/`, `/species`, `/variety/`, `/breed/` — interface-route-policy.ts:262-317), a deeper path is rewritten too, so their catch-all is never reached: address namespaces get the proxy 404 (rule 3) on a document request, and anything else lands on a `[locale]` path no route matches (e.g. `/uk/guides/a/b`), i.e. Next's built-in not-found (by code reading, not measured). Families whose policy is an **exact** path (`/catalog`, `/journals`, `/knowledge`, `/feed`, `/bookmarks`, `/wishlist`, `/notifications`, `/privacy`, `/support`, `/first-publication-disclosure`, `/markets/ukraine|bulgaria`) and the unlocalized ones keep their catch-all live.

Consequences worth carrying into criterion 3:

- 23 catch-alls still answer **200 with a `noindex` not-found body** for real deeper paths, several of them in public namespaces a crawler can reach (`/catalog/x`, `/journals/x`, `/knowledge/x`, `/privacy/x`, `/support/x`, `/markets/a/b`, `/sources/x`, `/lineage/x`, `/col|eppo|gbif|id|wikidata/a/b`). That is the documented residue of ADR-0029 D3, not a new defect, but it is not the "real 404 document" the address law asks for. `/markets/{unknown}` is the same soft 404 through `(default)/markets/[market]/page.tsx` (it is not an address prefix, so no proxy rule catches it).
- 9 catch-alls (`answers`, `blog`, `breed`, `communities`, `guides`, `journal`, `species`, `topics`, `variety`) are dead code since the default-locale rewrite; `missing-route.test.tsx` keeps requiring them.
- The `[locale]` tree has **no** catch-all. A prefixed three-segment path under a section with no such route (`/bg|ru/{catalog, journals, knowledge, feed, bookmarks, wishlist, privacy, support, first-publication-disclosure, notifications, lineage, sources}/{x}`) passes every proxy rule (the section is in `LOCALE_ROUTE_SEGMENTS`) and is matched by `[locale]/[profileHandle]/[entrySlug]/page.tsx` with `profileHandle` = the section name; `redirectLegacyJournalEntry` then checks the name's shape, looks a passing name up in the database, logs an address refusal and calls `notFound()` behind `[entrySlug]/loading.tsx` → **200 soft 404** (by code reading: app/legacy-journal-entry-route.tsx:27-60, src/lib/address/route-segments.ts:30-32, root-route-segments.ts:129-179).
